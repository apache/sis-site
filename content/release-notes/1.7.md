* Requirement: Java 11
* EPSG version: 13.101

Following the [retirement of Apache Derby](https://db.apache.org/derby/#Derby+Retired),
this release migrated the `org.apache.sis.referencing.database` module (Maven artifact: `sis-embedded-data`) to HSQLDB.
This change brings the following known issues (links to issues tracker are given):

* `sis-embedded-data` does not work if HSQLDB is on the module-path
  ([HSQLDB-1761](https://sourceforge.net/p/hsqldb/bugs/1761/)).
* `sis-embedded-data` causes _"A terminally deprecated method in sun.misc.Unsafe has been called"_ warning
  ([HSQLDB-1752](https://sourceforge.net/p/hsqldb/bugs/1752/)).
* `sis-embedded-data` may be very slow
  ([HSQLDB-1758](https://sourceforge.net/p/hsqldb/bugs/1758/)).
  As a workaround, `sis-embedded-data` unzips the database in a temporary directory,
  but this workaround may not be applicable in all environments.
* Some [command-line examples](../command-line.html#identifier) are temporarily broken because of collation issue.

Applications connected to their own database should instead use the `org.apache.sis.referencing.epsg` module
(Maven artifact: `sis-epsg`) in order to leverage their existing database engine and avoid above issues.
For example, Apache SIS works well on PostgreSQL.


# Security    {#security}

This release fixes the following vulnerabilities.
Before the fixes, parsing a small crafted file could cause an `OutOfMemoryError`,
or cause the parsing of other files at arbitrary URLs (local or distant), or allow SQL injection
(`org.apache.sis.storage.sql` module only; the metadata and referencing modules are not impacted).
Note that when Apache SIS opens another file, it tries to parse it as GML, GeoTIFF, NADCON or NTv2
format and fails at the first error. Therefore, these vulnerabilities are unlikely to leak sensitive
information (unless passwords are saved as TIFF images…).

* [CVE-2026-110748](https://www.cve.org/CVERecord?id=CVE-2026-110748) —
  Improper limitation of paths to GML, GeoTIFF, NADCON or NTv2 files
  * CWE-918 SSRF and local-file disclosure via `xlink:href` resolution during XML unmarshalling (reporters: n0mi1k, Ho1aAs).
  * CWE-918 SSRF via datum-shift grid-file references such as URI parameter in WKT (reporters: n0mi1k, Ho1aAs).
  * CWE-22 path traversal / arbitrary file read via Landsat metadata band filenames (reporters: n0mi1k, Ho1aAs).
* [CVE-2026-110733](https://www.cve.org/CVERecord?id=CVE-2026-110733) —
  SQL injection via unvalidated `ORDER BY` sort expression in the SQL feature store (reporter: Ho1aAs).
* CWE-770 unbounded memory allocation in the binary file parsers (netCDF + GeoTIFF) leading to DoS (reporter: n0mi1k).

The following vulnerability has not been fixed by code.
Instead, it is addressed by documenting recommendations:

* SQL injection on MySQL/MariaDB via missing backslash escaping (reporter: Ho1aAs).

See the [Security Policy](https://github.com/apache/sis/blob/main/SECURITY.md)
for recommendations about how to use Apache SIS in a security-sensitive context.
Thanks to "n0mi1k Security" and to Ho1aAs (GitHub: @HolaAsuka) for these reports.


# Incompatible changes    {#compatibility}

The following changes in Apache SIS 1.7 are incompatibles with the previous release (SIS 1.6):

* `JoinFeatureSet.condition` field has been made private because it was exposing a non-public type.
* `StoreListener.eventOccured(…)` method has been renamed `eventOccurred(…)` (fixed a typo in method name).
* `RecentReferenceSystems.setGridReferencing(…)` argument changed: `Map` keys changed from `String` to `Identifier`.
* `xlink:href` attributes in XML files are no longer followed by default if the referenced file is not in the same
  directory, or in a sub-directory, of the document containing the reference (see above security section).
  For following all URLs as before, set the `XML.RESOLVER` property to `ReferenceResolver.FOLLOW_EXTERNAL_XLINK`.
